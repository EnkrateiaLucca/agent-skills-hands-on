A Skill is a folder
with a markdown file in it.

That's it. That's the whole form factor.

So why a folder?

An LLM only ever sees text.

Everything piles up in one place:
the context window.

Every turn, the model re-reads all of it,
from the very first message.

And the window has a limit.

128k · 200k · 1M tokens.
1M tokens ≈ 750k words ≈ 1,500 pages.

An agent is that same model, in a loop with tools.

Every lap lands in the same window. Agents fill it fast.

More context isn't free.

It gets lost.
Too many instructions at once: it quietly drops some.
It hallucinates more.
It invents details and mixes up sources.
It gets slower and costlier.
Every turn re-reads the whole window first.

So keep the window short and focused.

Chroma, 2025: 18 frontier models, simple tasks. Reliability falls as input grows · the exact curve varies by model and task

One real sponsorship email, three setups

“Could you please share your pricing?” That question is the task.

CHAT · − AGENCY Has the email. Nothing else. Fluent prose that breaks my rules in sentence one. Good writing was never the bottleneck.
COWORK · + AGENCY Gains tools: finds the thread, reads the negotiation, drafts in place. Still missing the process. Nothing tells it how this job is done here.
COWORK + SKILL · + EXPERTISE A written-down workflow: what to check, when to stop, how to price. Same model. Same tools. One folder added to disk.

Agency gets you there faster. Expertise gets you somewhere right.

How do we bring our expertise into an agent?

WITHOUT SKILLS Load all of it, always.
30–50k tokens
50 Skills in the window, before anyone speaks.
10 Skills ≈ 6–10k tokens, every turn.
Worse, not just pricier.
WITH SKILLS Write your expertise once. The agent loads it only when the task needs it.

Three kinds of knowing, three homes.

Where the human sits: two gates, written as prose

One folder: a SKILL.md, 4 references, 2 scripts. The gates are two paragraphs.
No gate-handling code exists.

The description is the router.

---
name: sponsor-reply
description: Research an inbound sponsor and
  draft the reply. Use this whenever Lucas
  mentions a sponsor, sponsorship, brand deal,
  asks "is this one worth it",
  "what should I charge for a video" ...
---

What · When · Key functionalities.
The When is the hard part: write the words a user actually types.

A Skill that never fires can't be wrong about anything else.

Progressive disclosure: three levels

LEVEL 1 · ALWAYS IN CONTEXT
name + description
~100 tokens per Skill
LEVEL 2 · WHEN THE SKILL TRIGGERS
the SKILL.md body
usually < 5k tokens
LEVEL 3 · ONLY IF A STEP NEEDS IT
linked files: references, scripts, assets
scripts run outside: only their output comes in

The file system becomes just-in-time knowledge retrieval. That's why a Skill is a folder.

Skills live in the harness: one component, swappable and portable.

The “and” test

Describe the Skill in one sentence, with no and.

Creates Anki cards from any input→ ONE SKILL
Creates Anki cards and posts summaries to Notion→ TWO SKILLS IN ONE HAT · A “FRANKENSTEIN SKILL”
Clear success criteria
Define the rubric before the prose.
Single responsibility
One artifact type: many inputs, one output.
Defined inputs & outputs
Asks for what it needs before producing anything.
Stateless
Never silently assumes state it didn't ask for.
Progressive disclosure
The body decides what; references say how well.
Easily verifiable
Checking it costs less than writing it.

Verification must be cheaper than generation, or the Skill saved you nothing.

The rubric is the ceiling: your 15% is the part you cannot write down.

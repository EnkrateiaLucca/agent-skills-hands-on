Test yourself: Why does exponential backoff beat a fixed retry delay?

Because it spreads retries progressively further apart as failures persist, which prevents a "thundering herd" of clients all retrying in lockstep and overwhelming a recovering service.

✍️ Explain it first: In your own words, why is idempotency required for safe retries? Write it, THEN reveal.

Reveal model answer (compare against yours)

Retries can deliver the same request more than once. If the operation is idempotent, repeated delivery has the same effect as one delivery, so a duplicate retry can't double-charge, double-insert, etc.

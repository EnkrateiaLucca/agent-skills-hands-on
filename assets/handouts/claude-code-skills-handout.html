Claude Code and Agent Skills: the basics

Claude Code is an AI agent that works in your terminal. Agent Skills are folders of instructions and scripts that teach it a specific job. This sheet covers both on three pages.

O'Reilly Live Training · Lucas Soares Made by Lucas Skills

Part 1

What Claude Code is

Claude Code runs Claude as an agent. You describe an outcome, and Claude reads files, runs shell commands, edits code and checks its own work until the job is done.

It runs in the terminal, in VS Code and JetBrains, in a desktop app and on the web. Every surface shares the same settings, memory and Skills.

Install and start

# macOS / Linux
curl -fsSL https://claude.ai/install.sh | bash
# or with npm
npm install -g @anthropic-ai/claude-code

cd my-project
claude          # interactive session
claude -p "…"   # one-shot, scriptable
claude -c       # continue last session

The agent loop

1 · GATHER

Gather context

Search and read files, fetch docs, load a matching Skill.

Read Grep Glob WebFetch

→
2 · ACT

Take action

Edit files, run commands, call external tools.

Edit Write Bash MCP

→
3 · VERIFY

Check the result

Run tests, read output, compare with the goal.

Bash: pytest diff

↺ a failed check sends Claude back to step 1

Part 2

What an Agent Skill is

A Skill is a folder with a SKILL.md file. The file opens with YAML frontmatter (a name and a description) and continues with plain Markdown instructions. The folder can also hold reference documents and scripts. Claude reads the description, decides whether the Skill fits the request and loads the rest on its own.

Anatomy: the course's sponsor-reply Skill

sponsor-reply/ ├── SKILL.md entry point, required ├── references/ │ ├── research-playbook.md │ ├── rate-card.md │ ├── security-rubric.md │ └── reply-templates.md └── scripts/ ├── yt_stats.py fetches channel stats └── rate_calc.py computes the quote

References hold knowledge Claude reads when needed. Scripts handle deterministic work like API calls and arithmetic.

SKILL.md

---
name: meeting-notes
description: Turn a meeting transcript
  into notes with decisions, owners and
  deadlines. Use when the user shares a
  transcript or recording, or says
  "summarize this call" or "what did
  we decide".
---

# Meeting notes

1. Read the transcript.
2. List each decision with its owner.
3. List action items with deadlines.
4. Use the format in
   references/template.md.

Progressive disclosure: how a Skill loads

Claude never loads every Skill in full. It loads each one in up to three levels, and stops at the level the task needs. You can install dozens of Skills and pay almost nothing for the ones a task doesn't use.

Level 1 · always

Name + description

Loaded at startup for every installed Skill. Roughly 30–200 tokens each.

Level 2 · on match

SKILL.md body

Read when a request fits the description. Keep it under about 500 lines.

Level 3 · on demand

References and scripts

Opened when the instructions point there. A script runs, and only its output enters context.

Part 3

Writing a Skill that works

The description decides when it fires

Claude picks a Skill by reading its description, so the description carries the most weight in the file.

  • Say what the Skill does and when to use it.
  • List the phrases people actually type: "summarize this call", "what did we decide".
  • Name the inputs it handles: a transcript, a PDF, a URL.
  • Write in the third person and stay under 1,024 characters.
Weak

description: Helps with meetings.

Strong

Turn a meeting transcript into notes with decisions and owners. Use when…

The body: instructions Claude can follow

  • Write steps in order, the way you'd brief a new colleague.
  • Explain why a rule exists, so Claude handles edge cases well.
  • Move long reference material into references/ and link to it.
  • Put repeatable logic in scripts/. Code is cheaper and more reliable than reasoning through the same steps every time.
  • Add a gate wherever a human must approve: sending, paying, running outside code.
  • Test with real requests, and rewrite the description when the Skill misfires.

Where to put a Skill

Personal

~/.claude/skills/<name>/

Works in every project on your machine.

Project

.claude/skills/<name>/

Commit it, and your team gets it on clone.

Plugin or Claude.ai

/plugin install or upload a zip

Share through a marketplace, or use in the Claude apps.

Your first Skill in five minutes

mkdir -p ~/.claude/skills/meeting-notes
cd ~/.claude/skills/meeting-notes
$EDITOR SKILL.md     # frontmatter + steps
claude               # start a new session
> summarize this call transcript

Checklist before you share it

  • name: lowercase letters, numbers and hyphens
  • The description says what it does and when to use it
  • SKILL.md stays under ~500 lines
  • Long material lives in references/
  • Scripts run on their own and print clear output
  • No API keys in the folder. Use .env
  • Three real requests trigger it correctly
